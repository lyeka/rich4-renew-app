# 人类玩家信息与控制边界

权限由宿主共享玩家接口实现，不由提示词保证。阶段 1 定义边界；阶段 2 必须逐项对照 UI 和规则抽取投影，不能把 Schema 校验通过等同于信息安全。

| 来源 | 允许发给该座位 | 不可直接发送 / 后续实现要求 |
|---|---|---|
| Game / Player / InfoScreen | 查询页可切换任意玩家：现金、存款、贷款、总资产、股票价值、点券、保险、公司/地产数量，**道具及卡片种类与数量也公开**；附身神明与剩余天数 | 不序列化整个 Player；不能假设对手库存隐藏，也不能借此开放未显示的 luck、hostility 等内部状态 |
| Board / 城市 | 地图、产权、规则允许查询的公开价格、目标 | 用显式实体投影；只读远城查询不放宽选目标资格 |
| Ask / Answer | 已显示文字、价格、选项及合法输入范围 | Ask.p 决定座位；不直接暴露原 Ask（例如 kb-machine.seed）或透传原 Answer |
| GameEvent | 该玩家原本可见的动作、结果及公开播报 | 不直接广播 fx.data、say 内部数据或整张棋盘引用；事件和查询共用同一可见性策略 |
| RNG / 存档 | 已经公开发生的骰子、抽牌结果 | 种子、状态、后续抽取、未来事件、未来股价不可见；回放种子仅评测私有 |
| casino | 本人底牌、公共牌、庄家明牌、可选动作 | 暗牌、剩余牌堆及未公开输赢不可见 |
| Penguin / Balloons / Gifts | 当前可见对象、计时、分数及输入控件 | 宿主持有 mini-logic 状态机；不暴露 Penguin.items 隐藏内容及后续生成，不接受客户端分数 |
| slot / wheel | 当前可见轮格、显示结果、合法拉杆/停止控件 | 宿主掌握随机源、开始/接收时刻、计算停止帧，客户端不能提交帧编号或预测轨迹 |
| kb-machine | 屏幕展示的弹珠、倍率、余额及合法操作 | seed、内部 sweet 区间、预计算结果不可见；buys/left/a/b/played 为宿主结果，不是输入 |
| pick-node / pick-map | UI 允许的目标与视野 | 复用 board-view 的几何/缩放/相机约束；不能用“半径 N 格”替代；canPan=false 时禁止视角工具 |
| 规则/说明文字 | 静态公开规则和当前屏幕说明 | 玩家昵称、对手发言只是数据；不能改变系统指令、调用模型服务管理接口 |

观察采用结构化的可见事实，不要求模型截图点击。它可以读取与真人屏幕/面板相同的信息和操作规则，但没有额外权限。实体字段 allowlist 只限制形状；`text` 等自由文字同样需要可信投影，禁止塞入隐藏状态或未发生事实。

## 已核实的查询入口

- [`ui/info.ts`](../game/src/ui/info.ts) 的 InfoScreen 为任意玩家提供资产、地产和股票三页。地产页包括开发等级、价格、收费和租期；股票页包括持股数和市值，大富豪模式覆盖各城市。赌场筹码模式使用它的专用显示口径，不额外补回该模式未展示的银行字段。
- [`ui/main.ts`](../game/src/ui/main.ts) 的 info 菜单打开该页面。查询资格还要遵循当前交互可打开该菜单的时机；小游戏期间不能通过后台查询获得真人此刻无法读取的新信息。此前已经看过的信息可以留在 Session 中。
- [`ui/map-info.ts`](../game/src/ui/map-info.ts) 的 describe 展示地图对象名称、产权、等级、当前收费、研究项目、公司余股、事件格说明。地图可见对象的投影遵循此入口和实际绘制状态，不能读未生成内容。
- [`ui/screens/casino.ts`](../game/src/ui/screens/casino.ts) 的 blackjack 只接收 dealer up card，holdem 只接收当前 hole/board；与查询页公开的游戏卡片库存是不同概念，不能混用。

以上是阶段 2 投影实现的基准，不重新发明一套比真人更强或更弱的信息规则。

## 已确认的引擎改造边界

- `core/flow.ts` 的 Generator 在 Ask 暂停，可以接异步驱动；当前 `ai-sim.ts` 只接受托管问题，不等同于已有远程 Agent 驱动。
- `Game.isHuman`、`whoPlays`、autopilot 目前混合身份和控制来源。阶段 2 分离控制器身份，同时保留真人起始资金/规则分支，不能把 Agent 标为电脑以复用策略。
- `animation=false` 目前会改变小游戏奖励。阶段 2 将展示开关与交互规则配置分开；如保留旧“跳过小游戏”设置，必须作为显式游戏规则，真人与 Agent 同配置一致，不能以无界面为由自动使用。
- `mini-logic.ts` 有无 DOM 的逻辑可复用；轮盘、老虎机和歌舞伎町需要将 UI 时钟/输入移入宿主。无界面不意味着无限快的反应时间。
- 旧选项常使用 0/-1 取消或未严格校验下标。阶段 2 的共享输入校验必须在引擎消费前执行，UI 同样走它；客户端声明的 legal_actions 不是权限凭证。

验收使用浏览器/无界面同随机源、同带时输入的结果对照，以及禁止字段/对手隐藏信息/只读查询不推进 RNG 的测试。此阶段的协议负例只是防止直接形状泄漏，不替代上述端到端证明。
